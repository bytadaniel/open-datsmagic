# FE-021: Сессионный файл лидерборда команд

## 1. Контекст

Предоставить видимую оператору статистику команд без изменения контракта Desert API и без публикации auth tokens.

## 2. Архитектурное решение

- Каждый `CarpetState` хранит текущий личный `gold` и lifetime `gold_collected_total`; `PlayerState` хранит агрегированный session gold_collected и distance_travelled. Число потерянных ковров выводится из lifetime `death_count` всех ковров.
- При сборе bounty номинал зачисляется конкретному ковру и в `player.score`; при его гибели из этих сумм вычитается настраиваемый процент (`carpet_death_loss_percent`, default 30), но только личного баланса погибшего ковра.
- Пространственный resolver прибавляет значение монеты при её фактическом сборе и длину каждого tick-сегмента активного ковра. Респавн-телепорт исключён.
- Сервер на старте атомарно сбрасывает `leaderboard.json`, затем раз в секунду строит строки из snapshot и атомарно заменяет JSON-файл через временный файл + rename.
- Токен используется только как внутренний ключ. Display name строится детерминированно из токена через четыре словаря по 32 слова каждый (свыше миллиона комбинаций); токен никогда не сериализуется.
- Перед публикацией текущего snapshot имена проверяются на уникальность. При совпадении генератор пробует следующее salt-derived сочетание; имена команд остаются неизменными в пределах серверной сессии. Это поддерживает как минимум 10 000 одновременных команд.
- Визуализатор `lib/arena-visualizer` читает тот же локальный файл, обновляет его содержимое и открывает отдельное окно кнопкой/клавишей `L`. Он определяет строку своего токена по тому же генератору словесных имён и отмечает её как «Ваша команда».
- Пользовательское имя команды можно задать в визуализаторе; оно хранится локально для данного токена и заменяет сгенерированное имя только в этой визуализации. Публичный сессионный JSON и серверный API остаются неизменными.

## 3. Формат

```json
{
  "updated_at_unix_ms": 1790900000000,
  "teams": [
    {"rank": 1, "team": "Amber-Solar-Falcon-Mint", "gold": 3200, "gold_collected": 4100, "carpets_lost": 3, "distance_travelled": 18234.5}
  ]
}
```

Путь по умолчанию — корневой `leaderboard.json`; `DATS_LEADERBOARD_PATH` переопределяет его для сервера и Hub-оркестратора. Файл сессионный и заново инициализируется каждым новым серверным процессом. Rust-визуализатор читает публичный агрегированный лидерборд только через Hub API (`GET /api/leaderboard`), а не из этого файла.

## 4. Проверки

- Unit: коллекция увеличивает current gold и lifetime gold; штраф уменьшает только current gold.
- Unit: пройденная длина равна сумме отрезков и не содержит teleport после respawn.
- Unit: сериализованный JSON не содержит токен; сортировка стабильна.
- Unit: одинаковый токен всегда даёт то же имя; набор из 10 000 тестовых токенов получает уникальные имена.
- Integration: при старте создаётся пустой JSON, затем обновляется с активными игроками.
- UI: окно показывает четыре метрики и пустое состояние до подключения команд.
- UI: команда текущего токена явно отмечена; заданный пользователем локальный псевдоним сохраняется между запусками визуализатора.
