# FE-023: Веб-страницы, регистрация команд и лидерборд control plane

## 1. Контекст и цель

Дать игрокам единый адрес для документации, регистрации token/name и изучения результатов отдельных запусков и их агрегатов.

## 2. Страницы

- `/` — ссылки на документацию, leaderboard, регистрацию и активные арены; публичное название проекта — StadMagic. На главной есть заметное пояснение о вдохновении DatsMagic, ссылка на официальный сайт Dats.Team и явное указание, что это неофициальная независимая реализация, не претендующая на связь с Dats.Team, с готовностью закрыть серверы и доступ по их запросу.
- `/arena` — адаптивная Canvas-визуализация активной арены и ручное управление выбранным собственным ковром; правила описаны в [FE-024](FE-024-web-arena-visualizer.md).
- `/docs` — правила мира, описание API и ссылка на полную серверную механику.
- `/leaderboard` — при открытии показывает текущую арену; переключение открывает каталог запусков с прямыми ссылками на таблицу каждой арены, сводку по профилю или по всем мирам. Каталог фильтруется по миру и листается страницами; текущая попытка явно закреплена/отмечена. Страница автоматически обновляется каждые 5 секунд.
- `/worlds` — каталог JSON-профилей через селект; его размер определяется `assets/worlds.json`, выбранный мир и полный `ServerConfig` видны в основной области страницы.
- Голосование на странице `/worlds` — зарегистрированная команда голосует за следующий мир и может изменить голос до выбора; страница показывает публичные счётчики.
- `/register` — форма token/name; повторная отправка с тем же token переименовывает команду.

## 3. JSON API

| Метод/путь | Контракт |
|---|---|
| `GET /api/worlds` | Каталог миров переменного размера из `assets/worlds.json` с ID/именами/описаниями/конфигурациями плюс состояние единственной активной арены |
| `GET /api/votes` | Публичные количества голосов по каждому профилю без идентификации команд |
| `POST /api/votes` | `{ "token": "...", "world_id": "..." }`; установить/изменить единственный голос команды за следующий запуск |
| `GET /api/runs?world=n&limit=50&offset=0` | Страница истории запусков и общее количество; `world` необязателен, `limit` 1–200 |
| `GET /api/leaderboard?scope=run&run_id=id` | Последний snapshot выбранного запуска |
| `GET /api/leaderboard?scope=world&world=n` | Суммарные метрики команд по выбранному порядковому номеру мира |
| `GET /api/leaderboard?scope=all` | Суммарные метрики по всей истории всех миров |
| `POST /api/teams` | `{ "token": "...", "name": "..." }`; upsert приватного реестра, ответ не возвращает token |
| `GET /api/docs/api`, `/api/docs/world` | Документы API и правил мира в Markdown |
| `POST /api/visualizer/move` | `{ "token"?: "...", "transports": [...] }`; с token Hub проверяет регистрацию, без token разрешает только read-only просмотр через внутренний observer credential. Для ручного управления принимает `manualCarpetId` и `leaseId`; игровой API не расширяется. |
| `GET /health` | Состояние control plane и число активных арен |

### Агрегаты

Основной ranking score — суммарное `gold_collected`. На страницах агрегатов показываются только суммарные (`total`) показатели с ясными подписями: число попыток, собрано золота, сумма золота на руках по снимкам запусков, потери ковров и пройденная дистанция. Метрики лучшей попытки (`top`) доступны в JSON API, но не перегружают веб-таблицу. Учитываются только запуски, где команда появлялась в отчёте арены.

## 4. Безопасность и ошибки

- Registry JSON и SQLite расположены под `apps/arena-hub/data/`; весь каталог игнорируется git.
- Token допускается только в POST body и приватном файле, никогда не отдается GET-ответами, HTML или публичным leaderboard.
- Голос принимается только для зарегистрированного токена; хранилище содержит командный fingerprint, а публичный endpoint возвращает только агрегированные количества.
- Hub arena processes проверяют токен по registry file с кешем, обновляемым при изменении файла.
- Неизвестные scope/run/world возвращают `400`/`404`; некорректный token/name — `400`.
- По умолчанию web bind — loopback. Публикацию наружу оператор включает явно переменной `HUB_HOST`.
- Конфигурации каталога получает от бинарника сервера отдельным read-only CLI-вызовом; каталог JSON хранится вне кода и БД.
- При смене активной арены выбор `/leaderboard` остаётся в режиме «Текущая арена» и переключает данные на новый run; исторические режимы не сбрасывают пользовательский выбор.
- Исторический запуск открывается прямой ссылкой `/leaderboard?run_id=...`; пагинация каталога не ограничивает возможность открыть сохранённую ссылку.

## 5. Тестирование

- Unit: суммирование totals для команд с несколькими попытками и профилями миров.
- Unit: токен отсутствует в HTML и публичном JSON.
- E2E: register → arena authentication → metrics ingestion → run aggregation → rename reflected historically; голос за мир меняется для команды и применяется к следующей арене.
