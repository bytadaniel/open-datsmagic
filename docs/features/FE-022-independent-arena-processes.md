# FE-022: Последовательный оркестратор арены

## 1. Контекст и цель

Одновременно работает только один arena server. Control plane выбирает случайный профиль из `assets/worlds.json`, даёт процессу работать 20 минут, сохраняет итог попытки и переключает арену на другой профиль.

## 2. Архитектурное решение

`apps/arena-hub` читает произвольное положительное число валидированных профилей из `assets/worlds.json` (через CLI того же сервера), выбирает следующий мир с учётом командного голосования и запускает arena-процесс с `DATS_WORLD_ID`, `DATS_WORLD_RUN_NAME`, `DATS_WORLDS_PATH`, `PORT` и runtime-путями. При Compose-развёртывании Hub через закрытый `arena-controller` создаёт отдельный контейнер Rust-арены на время конкретного запуска и останавливает его при завершении; без Compose сохраняется локальный запуск дочернего процесса. Имя и профиль заданы напрямую в JSON. Внутренние RNG процесса инициализируются runtime-энтропией; воспроизводимые RNG допустимы в тестах.

Tick всегда 200 ms. При запуске процесс пишет `current_world.json` с данными выбранного JSON-профиля в `apps/arena-hub/data/` (или по пути `DATS_WORLD_STATUS_PATH`). Лидерборд standalone-арены также хранится там. Hub задаёт общий путь состояния мира, а метрики каждого запуска пишет в отдельный каталог запуска. БД Hub хранит только world ID/номер/имя в истории запусков, но не конфигурацию профиля.

Supervisor опрашивает локальный файл метрик; через `HUB_RUN_SECONDS` останавливает процесс, сохраняет последний snapshot и запускает другую арену на ближайшей минутной границе. После сбоя применяется то же расписание.

## 3. Хранение

- `apps/arena-hub/data/registry.json` — приватный token/name registry.
- `apps/arena-hub/data/hub.sqlite3` — история запусков и статистика команд; без копии настроек миров.
- `apps/arena-hub/data/arena/` — временные файлы и логи запусков.
- `assets/worlds.json` — версионируемый каталог профилей, не БД и не генерируемый исходниками список.

## 4. Цикл попытки

1. Случайно выбрать профиль, отличный от предыдущего; создать run row `starting` с именем `world_{world_id}_{world_n}_{n}`.
2. Запустить дочерний arena process и записывать его журнал.
3. Раз в секунду сохранять актуальный снимок метрик в SQLite.
4. После 20 минут снять финальный snapshot и корректно остановить процесс.
5. Выбрать другой профиль и запустить его на минутной границе (`:00`), downtime до 60 секунд.

## 5. Проверки

- Unit: каталог миров загружается; выбор не повторяет предыдущий ID; неизвестный ID отклоняется.
- Unit: БД сохраняет ID/имя профиля запуска без конфигурационного JSON и seed.
- Integration: старт → отчёт → завершение → следующий процесс с другим профилем.
- API: зарегистрированный токен принимается, незарегистрированный отклоняется.
