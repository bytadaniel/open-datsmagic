# FE-019: Регистрация и распределенный спавн флота по токену

## 1. Контекст и бизнес-цель

Убрать общий центральный прямоугольник ковров и привязать жизненный цикл флота к клиентскому токену.

## 2. Архитектурное решение

`ensure_player` атомарно создаёт игрока по токену и размещает его 5 ковров через общий алгоритм поиска случайной безопасной точки. Респавн использует тот же алгоритм.

## 3. Схема базы данных (Prisma)

Не применяется: регистрация хранится в оперативном состоянии симуляции.

## 4. Алгоритмы и вспомогательные функции

Для каждого ковра используется `WorldSpatialEngine::find_safe_spawn_point`: случайная точка принимается только вне ядер аномалий и безопасной дистанции от живых ковров.

## 5. API-контракты и DTO

Изменений маршрута нет: единственный `POST /play/magcarp/player/move` регистрирует токен на первом запросе.

## 6. Обработка ошибок

Пустой токен возвращает `401`; чужой `transport.id` попадает в `Desert.errors`.
