# FE-014: Крупная арена, интерполированная визуализация и тактовая телеметрия

## 1. Контекст и бизнес-цель

Игровая карта должна давать больше пространства для маневра. Сервер также публикует фактическую стоимость каждого такта. Клиентская интерполяция отдельно определена в `visualizer_2/docs/features/FE-003-interaction-and-interpolation.md`.

## 2. Архитектурное решение

- Базовая арена: `2200 x 1600` мировых единиц; окно: `1280 x 800` пикселей.
- Линии координатной сетки отключены. Граница арены и ее центральный маркер сохраняются.
- Сервер сохраняет шаг `Δt = 0.2 с` из `docs/mechanics.md`.
- После полного конвейера `commands → physics → spatial → snapshot` сервер пишет `info`-лог с номером тика, затраченным временем, бюджетом `tick_duration` и остатком бюджета. Превышение бюджета остается `warn`.

## 3. Алгоритмы

```text
P_render = P_previous + (P_current - P_previous) * α
α = clamp(elapsed_since_current_snapshot / poll_interval, 0, 1)
```

Интерполяция применяется только к визуальному представлению и не отправляет команд на сервер, не изменяет игровой мир и не влияет на физику.

## 4. Критерии приемки

- [ ] AC-01: Стандартная арена равна `2200 x 1600`, окно равно `1280 x 800`.
- [ ] AC-02: На поле нет фоновой сетки.
- [ ] AC-03: Каждый такт публикует отладочную метрику затраченного времени и остатка бюджета.

## 5. Тестирование

- Rust: существующие тесты игрового цикла подтверждают завершение полного такта; форматирование лога не влияет на игровое состояние.
