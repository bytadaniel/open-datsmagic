# FE-024: Лёгкий адаптивный веб-визуализатор арены

## 1. Контекст и цель

Добавить в Hub `/arena` для визуального наблюдения и ручного управления. Основа — canvas 2D и неизменённый Desert API. Прогноз траекторий, сетка риска и многолучевой расчёт вне scope.

## 2. Архитектурное решение

- `modules/arena-hub/static/arena-visualizer.js` отвечает за Canvas, камеру, выбор сущностей, realtime snapshots и ввод; сетевой цикл не блокирует `requestAnimationFrame`.
- `modules/arena-hub/static/arena-visualizer.css` задаёт адаптивную компоновку и мобильный виртуальный стик.
- `modules/arena-hub/hub.py` отдаёт страницу/ассеты и `POST /api/visualizer/move`. Hub проверяет токен игрока либо использует закрытый observer credential, вызывает текущий arena host через `POST /play/magcarp/player/move` и передаёт снимок.
- Снимки и ручные команды веб-визуализатора идут по отдельному WebSocket каналу. Он выдаёт latest snapshot на тик (200 мс), коалесцирует устаревшие версии и не меняет REST API ботов. Lease ручного управления обновляется отдельным малым heartbeat.
- Для обзора: колесо/щипок — zoom, drag/стрелки — pan; кнопка слежения центрирует выбранную цель. Клик по ковру выбирает его, выбор не включает управление.
- Для управления: мышь задаёт экранный вектор от центра выбранного ковра к указателю, как в Rust-визуализаторе; его длина ограничивается `maxAccel` в CSS-пикселях и потому не зависит от zoom. На touch виртуальный стик задаёт направление/длину, экранный Y инвертируется в координаты мира.
- Анонимный наблюдатель использует тот же игровой POST с закрытым `DATS_OBSERVER_TOKEN`, который Hub передаёт процессу арены. Arena возвращает все ковры в `enemies`, оставляет `transports` пустым и не создаёт состояние игрока. Observer-команда с непустым `transports` отклоняется.
- Выбранный ковер показывает три вектора `velocity`, `selfAcceleration`, `anomalyAcceleration`; остальные ковры рисуются компактно.
- Монеты рисуются непосредственно из мировых координат: экранный радиус равен API-радиусу, умноженному на текущий масштаб. Их пути батчатся в Canvas, растровая карта мира не масштабируется.
- Синие аномалии — отталкивающие, красные — притягивающие. Ядро залито непрозрачным цветом, внешняя область влияния полупрозрачная.
- Fullscreen включается кнопкой и синхронизируется с нативной командой выхода браузера; CSS-компоновка использует пространство экрана на ПК и телефоне.
- Для player_2 используется совместимый FNV-1a hash токена и файл `lib/arena-bots/rust_bytadaniel/manual_control_<hash>.json`. Hub атомарно записывает lease с `carpetId`, случайным `leaseId` и сроком `now + 1000 ms`; обновляет каждые 200 мс. На штатное выключение снимает только lease с собственным `leaseId`. При падении клиента TTL возвращает управление боту.

## 3. API-контракт

### Hub endpoint

`POST /api/visualizer/move` остаётся совместимым fallback endpoint; основной браузерный контракт описан в [FE-026](FE-026-web-visualizer-realtime-channel.md).

```json
{
  "token": "registered-token",
  "transports": [{"id": "team_0", "acceleration": {"x": 12, "y": -8}}],
  "manualCarpetId": "team_0",
  "leaseId": "browser-session-uuid"
}
```

В режиме игрока Hub проверяет `token` по приватному registry. Неизвестный token — `401`. В анонимном режиме поле `token` опущено, `transports` обязано быть пустым, Hub использует только внутренний observer credential. При manual control `manualCarpetId` должен принадлежать команде, иначе Hub отклоняет запрос. Hub передаёт игровые команды в формате без полей `token` и lease. Успех возвращает полный Desert snapshot; ошибка арены возвращает её HTTP status и JSON body.

Токен никогда не включается в URL, логи, HTML или ответ. Временное состояние lease не включает токен.

## 4. Обработка ошибок

| Ситуация | Статус/поведение |
|---|---|
| JSON некорректен или превышен лимит тела | `400` |
| Токен неизвестен Hub | `401` |
| ID ручного ковра не принадлежит команде | `403` |
| Активная арена недоступна | `502` с коротким сообщением; браузер показывает reconnect |
| HTTP/ошибка игрового API | исходный статус и тело; UI оставляет последние валидные данные |

## 5. Проверки

- Hub: route проксирует token только в `X-Auth-Token`, path не содержит token; неверный токен не достигает игрового сервера.
- Arena: observer auth не создаёт player/fleet и отклоняет команды; снимок содержит все команды как enemies.
- Hub: anonymous request проксируется с observer token из конфигурации процесса, секрет не сериализуется клиенту.
- Hub: lease пишет лишь разрешённый ID команды, TTL ограничен 1 сек., lease другого клиента не удаляется.
- UI: pixel/world mapping корректно учитывает DPR, zoom, вертикальную инверсию и touch input.
- UI: bounty радиус масштабируется пропорционально zoom без растрового размытия.
- UI: fullscreen входит/выходит кнопкой и синхронизирует подпись при системном выходе браузера.
- UI: keyboard controls не перехватывают ввод в текстовых полях; двухпальцевый жест меняет zoom; одиночный pan не включает manual.
- Performance: circles монет рисуются двумя batch paths за кадр; за пределами viewport пропускаются; не создаётся крупный растровый слой мира.
- E2E: зарегистрировать token → получить снимок → выбрать свой живой ковер → включить manual → проверить команду и lease → выключить manual → подтвердить снятие/истечение lease.
