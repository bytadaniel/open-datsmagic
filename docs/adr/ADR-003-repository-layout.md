# ADR-003: Компонентная структура монорепозитория

## Контекст

Репозиторий вырос из прототипа в набор продуктов: симулятор арены, нативный наблюдатель, управляющий Hub и несколько независимых реализаций игроков. Старые названия `server`, `lib/arena-visualizer`, `players` скрывают роли и усложняют запуск, документация компонентов разделена между корнем и локальными папками.

## Решение

- `modules/arena-hub/` — Python control plane, HTML/CSS/JS страницы, API, supervisor, приватные runtime-данные.
- `modules/arena-runtime/` — внутренний lifecycle API процесса Rust-арены.
- `lib/arena-server/` — Rust simulation API и исполняемый процесс арены. Графические зависимости не входят в пакет.
- `lib/arena-visualizer/` — автономное Rust/egui приложение наблюдения и ручного управления.
- `lib/arena-bots/<player>/` — независимые реализации игроков, подключаемые как отдельные репозитории там, где это нужно; их поведенческая логика не становится частью сервера.
- `docs/` — единственный каталог проектных документов: ADR, domain, features и `components/<component>/` для локальных спецификаций компонентов.
- `assets/worlds.json` хранит каталог профилей миров; `scripts/` содержит единые точки запуска.
- Каждый Rust-продукт — независимый Cargo package/workspace со своим `Cargo.toml` и `Cargo.lock`; корневого Cargo-манифеста нет. Это не связывает зависимости приложений и явно разделяет сборку.
- Python-визуализатор удаляется как заменённый Rust-приложением; Python остаётся только у Hub.

## Последствия

- Каждый Rust-продукт собирается своей командой через `--manifest-path`; lock-файл фиксирует только его зависимости.
- Изменение корневых путей требует обновлять `CARGO_MANIFEST_DIR`, Hub paths, скрипты, ignore-правила и ссылки документации одновременно.
- Приватные `token.txt`, runtime JSON/SQLite и локальные npm/cargo артефакты не переносятся в публичные спецификации и остаются игнорируемыми.
- Веб-интерфейс Hub строится на семантическом HTML и локальных CSS/JS без runtime CDN-зависимостей; это сохраняет возможность локального и контейнерного запуска.

## Миграция

Перенос выполняется сохранением исходных каталогов/файлов и обновлением ссылок. Содержимое токенов не меняется. Удаляются только заменённый Python-визуализатор и воспроизводимые локальные build/dependency artifacts.
