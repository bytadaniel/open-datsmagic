# ADR-001: Архитектурный базис игрового сервера и подсистемы визуализации

## 1. Контекст и проблема

Разрабатывается высокопроизводительный сервер непрерывно-пошаговой симуляции игрового мира DatsMagic с физической моделью в реальном времени, большим числом динамических объектов (точек с векторными характеристиками) и частым пересчетом коллизий.

Ключевые ограничения и вызовы:
1. **Производительность и задержки**: Необходима предсказуемая работа игрового цикла без пауз сборщика мусора (GC pauses) и с минимальным потреблением ресурсов при масштабировании количества сущностей.
2. **Ограничение человеческого контроля над кодом**: Разработчик не владеет языком Rust. Вся кодовая база генерируется AI-агентом, что накладывает критические требования к самодокументированности, архитектурной чистоте, детальности комментариев и строгому соблюдению инженерных практик.
3. **Наблюдаемость и отладка**: Требуется наглядная визуализация симуляции в реальном времени, не усложняющая ядро игрового сервера.

---

## 2. Архитектурные решения (Декларативные предписания)

### 2.1. Технологический стек ядра симулятора: Rust
- **Предписание**: Разработать игровой сервер симуляции исключительно на языке **Rust**.
- **Локация кода**: Разместить исходный код сервера в каталоге `/server`.
- **Формат поставки**: Обеспечить сборку сервера в автономный бинарный исполняемый файл (директория артефактов сборки `/bin` или стандартный `target/release`).

### 2.2. Стандарты качества кода и кодогенерации AI-агентом
- **Исчерпывающее документирование**: Все модули, структуры (`struct`), перечисления (`enum`), трейты (`trait`) и публичные методы снабдить детальной документацией в формате `rustdoc` (`///` и `//!`) с пояснением физического и математического смысла параметров.
- **Инженерные принципы**:
  - Строго соблюдать **SOLID** (в особенности SRP, OCP и DIP через Rust `trait`).
  - Применять принципы **KISS** и **DRY**, избегая преждевременных и неаргументированных усложнений.
  - Активно использовать статический и динамический полиморфизм (`trait`, generics, dynamic dispatch при необходимости) для изоляции компонентов и минимизации логических ошибок.
  - Покрывать каждую подсистему изолированными юнит-тестами.

### 2.3. Архитектурная изоляция подсистемы визуализации: Python + REST API
- **Предписание**: Реализовать подсистему визуализации в виде отдельного автономного клиента на **Python**.
- **Связанность**: Запретить прямую интеграцию рендерера в бинарник сервера. Взаимодействие осуществлять исключительно по сети через публичный REST API сервера (`/api/game/state`).
- **Назначение**: Клиент визуализации выполняет функции телеметрии, инспекции состояния мира и отладки поведения сущностей.

## 3. Обоснование решений

| Решение | Преимущества | Компромиссы (Trade-offs) |
| :--- | :--- | :--- |
| **Rust для ядра** | Высочайшая скорость расчетов, потокобезопасность на уровне компилятора (`Send`/`Sync`), отсутствие GC-пауз, компактный бинарник. | Повышенные требования к качеству кодогенерации и документированию, так как человек не вносит правки вручную. |
| **SOLID + Traits** | Модульность, независимое тестирование компонентов физики, коллизий и сети, упрощение рефакторинга для AI-агента. | Небольшой объем шаблонного кода интерфейсов трейтов. |
| **Python для UI** | Скорость разработки визуализатора, богатая экосистема 2D-рендеринга (Pygame/Arcade), полная развязка от жизненного цикла сервера. | Сетевые накладные расходы HTTP (полностью нивелируются дискретизацией тиков в 200 мс). |

---

## 4. Последствия (Consequences)

### Положительные:
1. Ядро симуляции функционирует автономно с максимальной вычислительной эффективностью.
2. Прозрачность кодовой базы для человека гарантируется высокой плотностью комментариев и строгой структуризацией.
3. Визуализатор может запускаться, перезапускаться и модифицироваться независимо от игрового сервера.

### Отрицательные и риски:
1. Необходимость поддержания строгой синхронизации DTO и контрактов API между Rust-сервером и Python-клиентом.
2. Повышенная ответственность AI-агента за корректность работы с `borrow checker` и потоками в Rust.
