# DR-011: Настройки игрового мира

## 1. Бизнес-контекст

Мир — это явно заданный именованный профиль параметров в `assets/worlds.json`. Каталог содержит переменное число разнообразных, но ресурсно ограниченных профилей, включая особые режимы с одним ковром и без респавна и с десятью коврами без респавна. Каждый обычный профиль должен иметь различимую игровую фишку, которую можно объяснить через его реальные настройки; количество записей само по себе не является целью. Конфигурации и описания миров не генерируются алгоритмом и не хранятся в БД. При запуске Hub случайно выбирает один профиль; сервер применяет его настройки, а независимые runtime RNG используют новую энтропию процесса. Повторяемость конкретной случайной раскладки мира не является контрактом.

## 2. Сценарии использования

- Hub читает и проверяет каталог миров из `assets/worlds.json`, затем выбирает профиль случайно, не повторяя предыдущий непосредственно.
- Пользователь открывает `/worlds`, выбирает стабильный ID и видит описание и точные настройки профиля.
- Сервер публикует текущие `world_id`, порядковый номер, название, описание и применённую конфигурацию в runtime-файле для визуализатора.
- Тик сервера фиксирован на 200 мс и не может изменяться профилем мира.

## 3. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-01 | В `assets/worlds.json` содержится один или более уникальных миров с непустыми ID, названием, описанием и конфигурацией. Число профилей не зашито в приложениях. | Must have |
| FR-02 | Профили являются данными JSON, а не результатом генерации в коде или записями БД. | Must have |
| FR-03 | Hub выбирает профиль случайно, не повторяя непосредственно предыдущий, и передаёт серверу его ID. | Must have |
| FR-04 | Размер каждой арены не превышает 20 000 × 20 000 игровых единиц; тик всегда 200 мс. | Must have |
| FR-05 | Плотность монет различается между мирами: допустимы бедные профили примерно с 500–1 000 монет, обычные — с 4 000–7 000, богатые — с 8 000–12 000 одновременно доступных монет. | Must have |
| FR-06 | UI мира показывает его ID, название, контекстное описание и точную активную конфигурацию без seed. | Must have |
| FR-07 | В SQLite хранится только ID/номер/название мира вместе с историей запуска; профиль целиком туда не копируется. | Must have |
| FR-08 | Профили должны иметь ясно различимые механические особенности, отражённые и в параметрах, и в описании; дублирование каталога косметическими вариациями не считается разнообразием. | Must have |
| FR-09 | Каталоговые изменения сохраняют конфигурации миров `last-carpet-standing` и `king-of-the-hill`. | Must have |
| FR-10 | Каталог допускает профиль, в котором радиус ядра близок к радиусу воздействия, при этом оба остаются ограниченного размера относительно арены. | Should have |

## 4. Бизнес-правила и ограничения ресурсов

1. `assets/worlds.json` — единственный каталог профилей; в нём нет seed-полей.
2. Стабильный `id` используется для связи запуска с каталогом, но не задаёт генератор случайных чисел.
3. Размеры арен — от 8 000 до 20 000 по каждой стороне. Конфигурация вне этого диапазона не допускается.
4. Запас монет задаётся явно в JSON и ограничен сверху 12 000 для контроля памяти/CPU. Низкое число — намеренная характеристика бедных миров; квота ограничивает одновременный запас, а не общий сбор за запуск.
5. Профили различаются скоростью ковров, трением, размерами арен, количеством/скоростью/силой/радиусом влияния аномалий и запасом монет. Отдельные экстремальные, но валидные профили допускаются.
6. Все диапазоны упорядочены, квоты положительны и конечны, параметры проходят `ServerConfig::validate`.
7. Трение — множитель скорости за тик: меньшее значение быстрее гасит скорость, значение около 1 сохраняет инерцию.
8. Любые RNG для спавна используют временную runtime-энтропию и фиксированные тестовые значения только в тестах; runtime-энтропия не является ID мира и не сохраняется как seed мира.

## 5. Логическая модель

`WorldDefinition = { id, name, description, config }`. `config` задаёт overrides `ServerConfig`; сервер дополняет пропуски базовыми значениями, валидирует и публикует активный снимок. `current_world.json` — только runtime-информация и может пересоздаваться при каждом запуске. БД хранит `world_id`, `world_number` и имя запуска для истории/лидерборда, но не копию JSON-профиля.

## 6. Критерии приемки

- Каталог JSON содержит переменное число (не менее одного) уникальных профилей, валиден и не содержит сидов.
- Для каждого профиля сервер может десериализовать и проверить конфигурацию; максимальная арена не больше 20 000 × 20 000, запас монет не больше 12 000.
- Hub может перечислить каталог и выбрать любой профиль без обращения к БД за настройками.
- Повторный запуск с тем же `world_id` сохраняет профиль, но не обещает повторяемую случайную раскладку сущностей.
- В API/визуализаторе нет seed-полей или seed-описаний.
