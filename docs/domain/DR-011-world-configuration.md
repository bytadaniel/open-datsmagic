# DR-011: Настройки игрового мира

## 1. Бизнес-контекст

Параметры карты, ковров, монет и аномалий должны настраиваться централизованно без поиска констант в нескольких модулях. Оператор сервера задаёт исходный профиль мира в одном конфигурационном файле.

## 2. Сценарии использования

- Оператор редактирует `world.json` перед запуском; сервер загружает его один раз при старте.
- Если файл неполон, незаданные параметры получают документированные значения по умолчанию.
- Невалидные диапазоны приводят к понятной ошибке запуска, а не к частично запущенному миру.

## 3. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-01 | Один файл задаёт размер арены, физику, лимиты ковров, число/номиналы монет и число/диапазоны аномалий. | Must have |
| FR-02 | Сервер применяет те же значения к начальному миру и последующему spawn/respawn. | Must have |
| FR-03 | При отсутствии файла или некорректных значениях сервер не стартует молча с неожиданными параметрами. | Must have |

## 4. Бизнес-правила

1. `world.json` загружается при каждом старте; горячая перезагрузка не входит в контракт.
2. Квоты аномалий и bounty относятся к максимальному одновременному количеству сущностей.
3. Нижняя граница каждого диапазона должна быть не больше верхней; радиусы и квоты неотрицательны.

## 5. Логическая модель

`WorldConfig` объединяет серверные параметры, геометрию/физику мира, генерацию монет и генерацию аномалий. Существующие механические правила DR-001/005/008 не меняются.

## 6. Критерии приемки

- Изменение значения в файле меняет соответствующий параметр нового мира.
- Частичный файл дополняется default-значениями.
- Неположительные размеры мира, некорректные интервалы и невозможные числовые значения отклоняются при запуске.
