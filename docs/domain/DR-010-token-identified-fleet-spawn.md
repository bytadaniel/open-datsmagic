# DR-010: Регистрация флота по клиентскому токену

## 1. Бизнес-контекст

Клиент сам выбирает непустой `X-Auth-Token`. Сервер по нему однозначно находит игрока либо создаёт нового; нельзя показывать каждому новому клиенту общий центральный флот.

## 2. Сценарии использования

| № | Участник | Действие | Результат |
|---|---|---|---|
| 1 | Новый клиент | `POST move` с новым токеном | Сервер регистрирует игрока и случайно размещает его 5 ковров на карте. |
| 2 | Тот же клиент | Повторяет запрос с тем же токеном | Получает и управляет только ранее созданными коврами. |
| 3 | Другой клиент | Использует другой токен | Получает независимый случайно размещенный флот. |

## 3. Функциональные требования

| ID | Требование | Приоритет | Примечание |
|---|---|---|---|
| FR-01 | Токен однозначно идентифицирует игрока. | Must have | Ключ `world.players`. |
| FR-02 | Новый токен создаёт ровно один флот. | Must have | Повторный запрос не создаёт дубликат. |
| FR-03 | Новый игрок получает ровно 5 ковров, случайно размещенных на карте. | Must have | Безопасные точки вне ядер аномалий и других ковров. |

## 4. Нефункциональные требования

| ID | Требование | Значение / Описание |
|---|---|---|
| NFR-01 | Безопасность спавна | Начальные точки и респавн используют ту же проверку безопасности. |
| NFR-02 | Изоляция | Команды могут ссылаться только на ковры текущего токена. |

## 5. Бизнес-правила

1. Пустой токен отклоняется с `401`.
2. Новый токен создаёт 5 ковров в случайных безопасных точках карты.
3. После гибели каждый ковер получает новую случайную безопасную точку респавна.

## 6. Модель данных

| Сущность | Ключевые атрибуты |
|---|---|
| `PlayerState` | `id = X-Auth-Token`, `carpets` |
| `CarpetState` | `id = {token}_{index}`, положение, лимиты движения |

## 7. API-контракты

| Метод | Путь | Назначение | Параметры |
|---|---|---|---|
| POST | `/play/magcarp/player/move` | Регистрация/опрос/управление флота | `X-Auth-Token`, `{ "transports": [] }` или команды |

## 8. Критерии приёмки

- [x] Новый токен создаёт 5 ковров в разных случайных точках карты.
- [x] Повторный запрос с тем же токеном возвращает те же ID ковров.
- [x] Команда чужого ID отражается в `errors`.

## 9. Вопросы и допущения

Коллизии между точками спавна разных токенов пока не разрешаются отдельно: размер карты 9000×9000 делает совпадение редким, а будущий спавнер сможет добавить поиск свободной позиции.
