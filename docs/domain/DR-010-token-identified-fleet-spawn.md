# DR-010: Выдача токена и регистрация флота команды

## 1. Бизнес-контекст

Токен — секрет доступа и стабильный идентификатор команды. Пользователь выбирает уникальное имя на сайте Hub, а Hub создаёт криптографически случайный токен и показывает его при регистрации один раз. Игровая арена сверяет каждый запрос с реестром Hub; пользователь не может самостоятельно зарегистрировать произвольный токен. Отсутствующий или неизвестный токен всегда отклоняется с HTTP 401. Секрет не должен попадать в URL, публичные отчёты, логи или игровые ID.

## 2. Сценарии использования

| № | Участник | Действие | Результат |
|---|---|---|---|
| 1 | Новый пользователь | Регистрирует уникальное имя в Hub | Получает один случайный секретный токен; имя команды уникально без учёта регистра. |
| 2 | Новый токен | Первый `POST /play/magcarp/player/move` с зарегистрированным секретом | Сервер создаёт заданное профилем число ковров и размещает их в безопасных точках. |
| 3 | Тот же токен | Повторяет запрос | Получает те же ID ковров, которые теперь основаны на непрозрачном ID команды, а не на открытом токене. |
| 4 | Неизвестный токен | Вызывает игровой API | Получает HTTP 401; игрок и флот не создаются. |

## 3. Функциональные требования

| ID | Требование | Приоритет | Примечание |
|---|---|---|---|
| FR-01 | Hub выдаёт токен только после регистрации уникального имени команды. | Must have | Случайный секрет показывается при создании один раз. |
| FR-02 | Новый токен создаёт ровно один флот. | Must have | Повторный запрос не создаёт дубликат. |
| FR-03 | Новый игрок получает число ковров из профиля мира, случайно размещённых на карте. | Must have | Обычно пять; профили могут задавать от одного до десяти. |
| FR-04 | Запрос без зарегистрированного токена отклоняется с HTTP 401. | Must have | Проверяется по приватному реестру Hub во всех режимах сервера. |
| FR-05 | API и публичные идентификаторы не раскрывают сырой токен. | Must have | Командный и carpet ID непрозрачны и стабильны. |

## 4. Нефункциональные требования

| ID | Требование | Значение / Описание |
|---|---|---|
| NFR-01 | Безопасность спавна | Начальные точки и респавн используют ту же проверку безопасности. |
| NFR-02 | Изоляция | Команды могут ссылаться только на ковры текущего токена. |

## 5. Бизнес-правила

1. Имя длиной 1–48 печатных символов уникально без учёта регистра.
2. Неизвестный или отсутствующий токен отклоняется с `401`.
3. Первый запрос валидного токена создаёт число ковров из профиля мира в случайных безопасных точках карты.
4. В игровых ответах вместо секрета используются имя команды и непрозрачные ID.
5. После гибели ковер получает новую безопасную точку только если в мире включён респавн.

## 6. Модель данных

| Сущность | Ключевые атрибуты |
|---|---|
| `TeamRegistry` | Секретный `token`, уникальное `name`, стабильный fingerprint `team_id` |
| `PlayerState` | `id = team_id`, `carpets` |
| `CarpetState` | `id = {team_id}_{index}`, положение, лимиты движения |

## 7. API-контракты

| Метод | Путь | Назначение | Параметры |
|---|---|---|---|
| POST | `/api/teams` | Создание команды по уникальному имени | `{ "name": "..." }`; ответ содержит созданный токен |
| POST | `/api/teams` | Переименование существующей команды | `{ "token": "...", "name": "..." }` |
| POST | `/play/magcarp/player/move` | Опрос/управление флота зарегистрированной команды | Выданный `X-Auth-Token`, `{ "transports": [] }` или команды |

## 8. Критерии приёмки

- [x] Новый зарегистрированный токен создаёт флот размера, заданного профилем, в разных безопасных точках карты.
- [x] Повторный запрос с тем же токеном возвращает те же ID ковров.
- [x] Команда чужого ID отражается в `errors`.

## 9. Вопросы и допущения

Коллизии между точками спавна разных токенов пока не разрешаются отдельно: размер карты 9000×9000 делает совпадение редким, а будущий спавнер сможет добавить поиск свободной позиции.
