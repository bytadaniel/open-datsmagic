# DR-013: Оркестрация арен и общий лидерборд

## 1. Бизнес-контекст

**Проблема / Возможность:** отдельные арены живут бесконечно, а результаты не собираются между запусками и мирами. Команде негде зарегистрировать отображаемое имя и посмотреть агрегированные результаты.

**Цель:** выделенный control plane поддерживает одну активную арену, управляет последовательными 20-минутными попытками, выбирая следующую арену по голосам команд или случайно при отсутствии голосов, ведёт приватный реестр токенов/имён и публикует документацию и лидерборд.

**Пользователи / Роли:** игрок регистрирует свой токен и имя; посетитель просматривает документацию и таблицы; оператор запускает/останавливает control plane.

**Ключевые метрики:** число активных арен и завершённых запусков; `gold_collected`, золото на руках, потери ковров и дистанция по запуску/миру/всем мирам.

## 2. Сценарии использования

### 2.1 Основной сценарий

| № | Участник | Действие | Результат |
|---|---|---|---|
| 1 | Control plane | Загружает каталог миров и запускает одну арену с выбранным профилем | Активно имя `world_{world_id}_{world_n}_{n}`, один arena-процесс и один arena-порт |
| 2 | Игрок | Регистрирует токен и отображаемое имя в веб-форме | Пара хранится в закрытом gitignored-файле; имя появляется в лидерборде |
| 3 | Команды / Control plane | Команды голосуют за следующий мир; после 20 минут control plane фиксирует результат и выбирает победивший профиль, либо случайный мир при отсутствии голосов | История попыток сохраняется между процессами; ничья разрешается случайно |
| 4 | Посетитель | Открывает `/leaderboard` | Видит текущие/завершённые попытки, статистику по миру и общий итог |

### 2.2 Исключительные ситуации

| Условие | Реакция системы |
|---|---|
| Арена завершилась раньше срока | Зафиксировать доступный последний snapshot и запустить выбранный голосованием или случайный профиль на минутной границе |
| Процесс не запускается | Отметить запуск failed, показать ошибку/лог, выбрать профиль по голосам или случайно и повторить на минутной границе |
| Реестр токенов отсутствует/повреждён | Создать пустой реестр при старте либо показать ошибку; не публиковать его содержимое |

## 3. Функциональные требования

| ID | Требование | Приоритет | Примечание |
|---|---|---|---|
| FR-01 | Одновременно запущен ровно один arena-процесс с одним профилем из `assets/worlds.json` | Must have | Имя `world_{world_id}_{world_n}_{n}` |
| FR-02 | Попытка арены длится 20 минут, после чего процесс останавливается, фиксируется результат и выбирается профиль следующей попытки | Must have | Голоса имеют приоритет; при отсутствии голосов выбор случайный |
| FR-03 | Токены и имена команд хранятся в локальном закрытом файле, исключённом из git | Must have | Сам файл никогда не отдается веб-клиенту |
| FR-04 | Игровые запросы через управляемый сервер принимают только зарегистрированные токены | Must have | В standalone-режиме арены может остаться dev-auth |
| FR-05 | Хранить per-run метрики золота, собранного золота, смертей ковров и дистанции | Must have | Команду связывать по непрозрачному стабильному team id |
| FR-06 | Показывать текущую/историческую попытку, агрегаты профилей и агрегат всех миров | Must have | Сводные таблицы показывают totals |
| FR-07 | Опубликовать страницу документации API и правил мира | Must have | Без публикации токен-реестра |
| FR-08 | Игрок может задать и переименовать отображаемое имя для своего токена | Must have | Upsert по токену |
| FR-09 | Зарегистрированная команда может отдать один голос за следующий профиль и менять выбор до его фиксации при старте следующего запуска. | Must have | Токен проверяется на сервере, наружу показываются только счётчики |
| FR-10 | Если голоса есть, выбирать профиль с максимальным числом голосов; ничью разрешать случайно. Если голосов нет — выбирать профиль случайно. | Must have | Голоса сбрасываются после выбора профиля |

## 4. Нефункциональные требования

| ID | Требование | Значение / Описание |
|---|---|---|
| NFR-01 | Сохранность истории | Транзакционная локальная SQLite БД |
| NFR-02 | Изоляция запусков | Разные последовательные процессы, профили и runtime-каталоги; arena-порт переиспользуется |
| NFR-03 | Секретность | Реестр и история с token id не коммитятся; токен не входит в публичные DTO |
| NFR-04 | Доступность control plane | HTTP bind configurable; безопасное значение по умолчанию `127.0.0.1` |

## 5. Бизнес-правила

1. Имя запуска — `world_{world_id}_{world_n}_{n}`: `world_id` — стабильный ID профиля из JSON; `world_n` — номер его использования; `n` — общий номер запуска.
2. «Попытка» — один процесс арены от успешного старта до завершения/ошибки; лимит runtime — 20 минут. В любой момент активен максимум один процесс.
3. Следующая попытка запускается на ближайшей минутной отметке `:00` после остановки процесса; если остановка уже совпала с границей, повторного ожидания нет.
4. Голос учитывается по стабильному `team_id`, не по браузеру; одна команда имеет ровно один актуальный выбор на следующий запуск.
5. Снимок голосов потребляется в момент выбора следующего мира; более поздние голоса относятся уже к последующему выбору.
6. В таблице конкретного запуска показывается последний snapshot команды этого запуска.
7. В сводных группах все метрики суммируются по попыткам команды; профиль мира фильтруется по порядковому номеру каталога.
8. Имя берётся из актуального приватного реестра, при отсутствии — стабильное fallback-имя.
9. Публичные таблицы никогда не содержат токены и их исходные строки.

## 6. Модель данных

| Сущность | Ключевые атрибуты |
|---|---|
| Team | `team_id`, приватные `token`, публичное `name`, `updated_at` |
| ArenaRun | `run_id`, `world_number`, `world_id`, `world_name`, `world_occurrence`, `run_number`, `arena_name`, `port`, `started_at`, `ended_at`, `status` |
| RunTeamStats | `run_id`, `team_id`, `gold`, `gold_collected`, `carpets_lost`, `distance_travelled` |
| NextWorldVote | `team_id`, `world_id` — временное состояние Hub до выбора следующей арены |

## 8. Критерии приёмки

- [ ] Ровно одна арена запущена одновременно; следующий профиль выбирается большинством голосов, а при отсутствии голосов — случайно из JSON-каталога.
- [ ] После рестарта арены предыдущий запуск остаётся в истории и агрегатах.
- [ ] Переименование через веб-форму отображается в текущих и исторических таблицах.
- [ ] Публичные endpoints не раскрывают token registry.
- [ ] Для каждого профиля и всей истории доступны суммарные метрики команд.

## 9. Вопросы и допущения

**Допущения:**
1. `top` ранжируется по одному основному показателю `gold_collected`; остальные поля top относятся к той же лучшей попытке.
2. Все попытки используют один настраиваемый arena-порт; control plane слушает отдельный порт.
3. Результаты публикуются как веб-таблица, polling API возвращает JSON.

## 10. Зависимости

- **Внутренние модули:** Rust arena server, `assets/worlds.json`, локальный runtime-экспорт метрик.
- **Инфраструктура:** Python 3 standard library, SQLite, локальный filesystem, один порт control plane и один переиспользуемый arena-порт.
