# DR-012: Сессионный лидерборд команд

## 1. Бизнес-контекст

Оператору нужно сравнивать команды, созданные разными токенами, по балансу золота, суммарно собранному золоту, потерям ковров и пройденному расстоянию.

## 2. Сценарии использования

- Сервер начинает новую сессию с пустой таблицей и заново создаёт `leaderboard.json`.
- Во время игры сервер обновляет сводку каждой зарегистрированной команды.
- Визуализатор открывает таблицу и показывает участвующие команды и их метрики.

## 3. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-01 | Лидерборд хранит текущий баланс золота, lifetime-сбор золота, число погибших ковров и пройденную дистанцию команды. | Must have |
| FR-02 | Текущий баланс учитывает штрафы за гибель; lifetime-сбор не уменьшается при штрафах. | Must have |
| FR-03 | Идентификатор авторизации (токен) не попадает в файл или UI; используются безопасные отображаемые имена команд. | Must have |
| FR-04 | Файл атомарно перезаписывается и сортируется по текущему золоту, затем по собранному золоту. | Should have |
| FR-05 | Визуализатор показывает команды и четыре метрики в отдельном окне. | Must have |

## 4. Бизнес-правила

1. Лидерборд сессионный: рестарт сервера обнуляет его и начинает новый файл.
2. `gold` — сумма текущих личных балансов всех ковров команды после потерь; `gold_collected` — сумма номиналов всех собранных монет без вычитания потерь.
3. `carpets_lost` считает каждую гибель стабильного ID ковра, включая смерти от аномалий, столкновений и выхода за границу.
4. `distance_travelled` — сумма длин фактически пройденных за игровые тики отрезков всех ковров команды; teleport при респавне не является пройденной дистанцией.
5. Строки команд не содержат исходные токены и сортируются детерминированно.

## 5. Логическая модель

`LeaderboardEntry`: display name/rank, `gold`, `gold_collected`, `carpets_lost`, `distance_travelled`. Идентификация команды внутри процесса связывается с токеном, но сериализуемая запись его не содержит.

## 6. Критерии приемки

- Новый запуск создаёт пустой файл до появления игроков.
- Сбор золота, штраф, гибель/респавн и движение отражаются в правильных независимых полях.
- Обрыв процесса во время записи не оставляет JSON наполовину записанным.
- Визуализатор умеет открыть/закрыть окно лидерборда и показать все зарегистрированные команды.
