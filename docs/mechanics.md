# Техническая спецификация игрового сервера DatsMagic

Данный документ описывает правила, физическую модель и API-контракты пошагово-непрерывного симулятора управления ковром-самолетом в условиях динамического окружения (пустыни).

---

## 1. Общие положения и игровой цикл

- **Игровая среда**: Двумерное непрерывное пространство (2D плоскость) с декартовой системой координат $(X, Y)$.
  - Ось **$X$** направлена вправо (возрастает вправо).
  - Ось **$Y$** направлена вверх (возрастает вверх).
- **Дискретизация времени (Game Loop)**:
  - Сервер работает циклично с фиксированным шагом времени (тиком):
    $$\Delta t = 0.2\text{ с } (200\text{ мс})$$
- **Сетевое взаимодействие**:
  - Синхронно-асинхронная модель.
  - В течение каждого тика игроки опрашивают состояние мира через `GET` и отправляют управляющие команды через `POST`.
  - В конце тика сервер атомарно обрабатывает все полученные команды, выполняет физический пересчет и обновляет состояние мира.

---

## 2. Физическая модель движения (Векторная механика)

### 2.1. Векторы состояния игрока

Каждая сущность игрока (ковёр-самолёт) описывается в оперативной памяти сервера следующими величинами:

| Обозначение | Название | Описание |
| :--- | :--- | :--- |
| $\vec{P} = (x, y)$ | **Координаты** | Радиус-вектор текущего положения ковра в пространстве |
| $\vec{V} = (v_x, v_y)$ | **Скорость** | Вектор текущей скорости ковра |
| $\vec{A} = (a_x, a_y)$ | **Ускорение** | Вектор управляющего ускорения (задается игроком) |
| $\vec{W} = (w_x, w_y)$ | **Силы окружения** | Результирующий вектор внешних сил (ветер, гравитационное затягивание аномалий) |

### 2.2. Константы и ограничения симуляции

| Параметр | Поле в API | Описание | Значение по умолчанию |
| :--- | :--- | :--- | :--- |
| $A_{max}$ | `max_acceleration` | Максимальный модуль вектора ускорения за один тик | Определяется сервером (например, $5.0$) |
| $V_{max}$ | `max_velocity` | Максимально допустимый модуль скорости ковра | Определяется сервером (например, $20.0$) |
| $k_{f}$ | `friction` | Коэффициент вязкого трения среды (воздух/песок), затухание за шаг | $0.98$ |

---

### 2.3. Алгоритм пересчета физики на каждом тике (схема Эйлера)

Пересчет физического состояния сущности выполняется сервером строго по следующим шагам:

#### Шаг 1. Валидация и нормализация команды игрока
Если длина заявленного игроком вектора ускорения превышает допустимый максимум ($\|\vec{A}\| > A_{max}$), сервер принудительно нормализует его:
$$\vec{A} = \frac{\vec{A}}{\|\vec{A}\|} \cdot A_{max}$$
Если игрок находится под действием эффекта оглушения (`stunned`), управление блокируется: $\vec{A} = (0, 0)$.

#### Шаг 2. Расчет сил окружения
На основе текущих координат $\vec{P}$ рассчитывается суммарное воздействие всех активных аномалий:
$$\vec{W} = \sum_{i} \vec{w}_i$$

#### Шаг 3. Интегрирование скорости с учетом трения
$$\vec{V}_{new} = (\vec{V}_{old} \cdot k_{f}) + (\vec{A} + \vec{W}) \cdot \Delta t$$

#### Шаг 4. Ограничение предельной скорости
Если модуль скорости превышает порог ($\|\vec{V}_{new}\| > V_{max}$), вектор направления сохраняется, но модуль усекается:
$$\vec{V}_{new} = \frac{\vec{V}_{new}}{\|\vec{V}_{new}\|} \cdot V_{max}$$

#### Шаг 5. Интегрирование позиции
$$\vec{P}_{new} = \vec{P}_{old} + \vec{V}_{new} \cdot \Delta t$$

## 3. Игровые сущности и правила взаимодействия

### 3.1. Ковры-самолеты (Игроки)

- **Радиус коллизии**: Точечный ($R = 0$) или минимальный физический радиус ($R_{player}$).
- **Статусы состояния**:
  - `normal` — штатное состояние, полное управление доступно.
  - `stunned` — оглушение (например, попадание в центр аномалии). При данном статусе переданный игроком вектор ускорения $\vec{A}$ принудительно обнуляется сервером:
    $$\vec{A} = (0, 0)$$

### 3.2. Сокровища (Treasures)

Сущности со статическими координатами $\vec{P}_{treasure} = (x, y)$ и ценностью в $S$ очков.

- **Механика сбора**: На каждом тике проверяется условие коллизии с игроком:
  $$\text{Distance}(\vec{P}_{player}, \vec{P}_{treasure}) \le R_{capture}$$
  где $R_{capture}$ — фиксированный радиус сбора.
- **Результат**: При выполнении условия игроку начисляются очки $S$, а сокровище удаляется с карты (или переспавнивается).

### 3.3. Динамические аномалии / Вихри (Anomalies)

Подробно специфицированы в документе предметной области [`docs/domain/DR-005-anomalies.md`](domain/DR-005-anomalies.md).

Подвижные области природной стихии, заданные:
- Центром $\vec{P}_{anomaly} = (x, y)$ и вектором скорости $\vec{V}_{anomaly} = (v_x, v_y)$
- Смертоносным ядром $R_{core}$ и внешней зоной воздействия $R_{effect}$ ($R_{core} < R_{effect}$)
- Типом воздействия `type`: `attracting` (притягивающая) или `repelling` (отталкивающая)
- Прирожденной силой воздействия $F_{influence}$

#### Механика воздействия:
1. **Смертоносное ядро**: Если дистанция от центра ковра до центра аномалии достигает $\text{Distance}(\vec{P}_{player}, \vec{P}_{anomaly}) \le R_{core} + R_{player}$, ковер мгновенно **уничтожается** (`status: "destroyed"`), исключается из физического расчета и визуализации.
2. **Внешняя зона влияния**: Если ковер находится в зоне $R_{core} < \text{Distance}(\vec{P}_{player}, \vec{P}_{anomaly}) \le R_{effect}$:
   - Для `attracting` (притяжение):
     $$\vec{W}_{anomaly} = \frac{\vec{P}_{anomaly} - \vec{P}_{player}}{\|\vec{P}_{anomaly} - \vec{P}_{player}\|} \cdot F_{influence}$$
   - Для `repelling` (отталкивание):
     $$\vec{W}_{anomaly} = \frac{\vec{P}_{player} - \vec{P}_{anomaly}}{\|\vec{P}_{player} - \vec{P}_{anomaly}\|} \cdot F_{influence}$$
3. **Движение и жизненный цикл**: Аномалия рождается в буферной зоне за пределами арены, прямолинейно перемещается через мир с постоянной скоростью $\vec{V}_{anomaly}$, обязательно пересекая арену зоной действия, и деспавнится после полного выхода за границы арены. Аномалии беспрепятственно проходят сквозь друг друга (ghosting), а их силы векторно суммируются.

### 3.4. Противники (Enemies)

Другие управляемые игроки в зоне видимости. Сервер передает их идентификаторы `id`, координаты `position` и текущие векторы скорости `velocity`.

## 4. Контракты API (Спецификация JSON)

### 4.1. Общие требования
- **Авторизация**: Каждый запрос к API должен содержать HTTP-заголовок:
  ```http
  X-Auth-Token: <строковый_токен_команды>
  ```
- **Формат данных**: `application/json` для тела запросов и ответов.

---

### 4.2. Получение состояния мира

Возвращает текущую картину игрового мира для управляемой команды на данном тике.

- **Метод**: `GET`
- **Эндпоинт**: `/api/game/state`

#### Успешный ответ (`200 OK`):

```json
{
  "tick": 1042,
  "game_status": "active",
  "player": {
    "id": "team_20",
    "score": 1420,
    "status": "normal",
    "position": { "x": 412.5, "y": 890.2 },
    "velocity": { "x": 8.5, "y": -4.1 },
    "max_acceleration": 5.0,
    "max_velocity": 20.0
  },
  "treasures": [
    {
      "id": "t_99",
      "type": "chest",
      "position": { "x": 450.0, "y": 920.0 },
      "value": 50
    }
  ],
  "anomalies": [
    {
      "id": "a_3",
      "position": { "x": 400.0, "y": 900.0 },
      "radius": 40.0,
      "force": 3.5
    }
  ],
  "enemies": [
    {
      "id": "team_5",
      "position": { "x": 430.0, "y": 910.0 },
      "velocity": { "x": 12.0, "y": 2.1 }
    }
  ]
}
```

#### Описание полей ответа:

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `tick` | `integer` | Номер текущего игрового тика |
| `game_status` | `string` | Статус игры (`"active"`, `"finished"`, etc.) |
| `player` | `object` | Состояние управляемого ковра игрока |
| `player.id` | `string` | Уникальный идентификатор команды/игрока |
| `player.score` | `integer` | Текущий счет команды |
| `player.status` | `string` | Статус ковра (`"normal"`, `"stunned"`) |
| `player.position` | `object` | Текущие координаты `{ "x": float, "y": float }` |
| `player.velocity` | `object` | Текущий вектор скорости `{ "x": float, "y": float }` |
| `player.max_acceleration` | `float` | Максимальный модуль вектора ускорения $A_{max}$ |
| `player.max_velocity` | `float` | Максимальный модуль вектора скорости $V_{max}$ |
| `treasures` | `array` | Список доступных сокровищ на карте |
| `treasures[].id` | `string` | Идентификатор сокровища |
| `treasures[].type` | `string` | Тип сокровища (например, `"chest"`) |
| `treasures[].position` | `object` | Координаты сокровища `{ "x": float, "y": float }` |
| `treasures[].value` | `integer` | Начисляемые очки за сбор |
| `anomalies` | `array` | Список активных аномалий/вихрей |
| `anomalies[].id` | `string` | Идентификатор аномалии |
| `anomalies[].position` | `object` | Координаты центра `{ "x": float, "y": float }` |
| `anomalies[].radius` | `float` | Радиус зоны воздействия $R_{anomaly}$ |
| `anomalies[].force` | `float` | Сила затягивания $F_{pull}$ |
| `enemies` | `array` | Список обнаруженных противников |
| `enemies[].id` | `string` | Идентификатор противника |
| `enemies[].position` | `object` | Координаты противника `{ "x": float, "y": float }` |
| `enemies[].velocity` | `object` | Вектор скорости противника `{ "x": float, "y": float }` |

### 4.3. Отправка управляющей команды

Отправляет вектор ускорения, который будет приложен к ковру на следующем тике симулятора.

- **Метод**: `POST`
- **Эндпоинт**: `/api/carpet/command`

#### Тело запроса (JSON):

```json
{
  "acceleration": {
    "x": 3.5,
    "y": -1.5
  }
}
```

#### Коды ответов:

| HTTP-код | Статус | Описание и формат ответа |
| :--- | :--- | :--- |
| `200 OK` | Успешно | Команда принята входным буфером текущего тика: `{"status": "accepted"}` |
| `400 Bad Request` | Неверный запрос | Переданы некорректные типы данных или нечисловые значения (`NaN`, `Infinity`) |
| `429 Too Many Requests` | Превышен лимит | Запросы отправляются чаще лимита Rate Limit (**рекомендуется строго 1 команда за 1 игровой тик**) |
