# DR-001: Запуск Node.js-клиента и подключение к арене

## 1. Бизнес-контекст

**Проблема / Возможность:** клиент читает токен из локального `token.txt`, а игровой сервер задаётся исходным кодом. Такой запуск плохо переносится между локальной ареной и публичным сервером.

**Цель:** передавать токен и endpoint через окружение, чтобы клиент можно было запускать без редактирования и хранения секретов в исходниках.

**Пользователи / Роли:** владелец зарегистрированной команды запускает Node-процесс и предоставляет свой Hub token.

**Ключевые метрики:** цикл API-клиента остаётся ниже лимита 5 запросов/с на токен; сетевые ошибки не превращаются в неконтролируемый retry loop.

## 2. Сценарии использования

### 2.1 Основной сценарий

| № | Участник | Действие | Результат |
|---|---|---|---|
| 1 | Игрок | Задаёт `DATS_PLAYER_TOKEN` и `DATS_GAME_API_URL` | Клиент проверяет конфигурацию до запуска цикла |
| 2 | Клиент | Посылает пустой пакет и получает Desert snapshot | Имеет валидное состояние арены |
| 3 | Клиент | Рассчитывает и посылает пакет команд | Arena авторизует запрос по `X-Auth-Token` и обновляет состояние |

### 2.2 Альтернативные сценарии

- Для другой арены меняется только `DATS_GAME_API_URL`.
- Для другой команды меняется только `DATS_PLAYER_TOKEN`.

### 2.3 Исключительные ситуации

| Условие | Реакция системы |
|---|---|
| Не задан token или URL | Остановить запуск с понятной диагностикой до первого HTTP-запроса |
| HTTP 401/400/403 | Не продолжать цикл с неверными credentials/данными |
| HTTP 429 | Сделать ограниченную паузу и повторить позже |
| Временная ошибка сети/сервера | Сообщить об ошибке и повторить без частого burst |

## 3. Функциональные требования

| ID | Требование | Приоритет | Примечание |
|---|---|---|---|
| FR-01 | Читать token и полный game endpoint из environment | Must have | Нет fallback к локальному token file |
| FR-02 | Передавать token только заголовком `X-Auth-Token` | Must have | Не включать секрет в body, URL или логи |
| FR-03 | Проверять HTTP status и валидно обрабатывать retry | Must have | 429 не должен рекурсивно вызывать неограниченную цепочку |
| FR-04 | Запускать сохранённый actioner штатной командой пакета | Must have | Алгоритм поведения остаётся прежним |

## 4. Нефункциональные требования

| ID | Требование | Значение / Описание |
|---|---|---|
| NFR-01 | Секреты | Не коммитить токен; не писать его в логи |
| NFR-02 | API frequency | Не превышать пять запросов/с на token |

## 5. Бизнес-правила

1. Клиент использует только `POST /play/magcarp/player/move` из общего Desert API.
2. Первый запрос передаёт `{ "transports": [] }`; дальнейшие запросы содержат команды транспорта.
3. URL — полный endpoint, включая `/play/magcarp/player/move`.
4. Изменение сетевой обвязки не меняет выбор цели и действия игрока.

## 6. Модель данных (логическая)

| Сущность | Описание | Ключевые атрибуты |
|---|---|---|
| `RuntimeConfig` | Переменные подключения | `DATS_PLAYER_TOKEN`, `DATS_GAME_API_URL` |
| `Desert` | Ответ арены | `transports`, `bounties`, `anomalies`, `enemies`, `mapSize` |
| `MovePayload` | Пакет команд | `transports[].id`, `acceleration`, опциональные действия |

## 7. API-контракты

Используется `POST /play/magcarp/player/move`, специфицированный в [`DR-009`](../../domain/DR-009-legacy-world-contract.md) и [справочнике API](../arena-hub/api.md). Новый endpoint не вводится.

## 8. Критерии приёмки

- [ ] AC-01: клиент запускается с URL и токеном из env без `token.txt`.
- [ ] AC-02: запрос содержит `Content-Type: application/json` и `X-Auth-Token`.
- [ ] AC-03: `401` и другие не-2xx ответы не разбираются как успешный `Desert`.
- [ ] AC-04: серверный 429 обрабатывается с паузой и без быстрого рекурсивного retry.
- [ ] AC-05: исходный actioner сохраняет алгоритм управления.

## 9. Вопросы и допущения

**Допущения:** среда Node.js содержит `fetch` и поддерживается runtime запуска TypeScript.

## 10. Зависимости

- **Внешние системы:** Arena API StadMagic и Hub token registry.
- **Внутренние модули:** `lib/arena-bots/nodejs_bytadaniel`.
- **Инфраструктура:** Node.js 22+ и npm.
