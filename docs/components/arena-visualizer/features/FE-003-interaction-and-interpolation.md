# FE-003: Плавное наблюдение и ручное управление

## 1. Контекст

Снимки API приходят реже графических кадров. Оператору нужны плавная картинка, отдельный выбор наблюдаемого ковра и явное включение ручного управления.

## 2. Snapshot buffer и интерполяция

Хранить два последних валидных snapshot и время получения каждого на monotonic clock. Рисовать мир с задержкой на один измеренный poll interval: `renderTime = now - pollInterval`, `alpha = clamp((renderTime-t0)/(t1-t0),0,1)`. Это обеспечивает непрерывное движение от предыдущего к текущему снимку и не возвращает объект назад при приходе очередного ответа. Интерполировать координаты ковров по ID, аномалий по ID и врагов по индексу только когда количество врагов совпадает в обоих снимках (сервер сортирует их детерминированно). Счет, status, bounty, anomaly type и управление никогда не интерполируются. Интерполяция — только presentation state.

Если изображения объектов интерполируются, векторы V/S/W компонентно интерполируются тем же alpha. Траектории прогнозов сдвигаются вместе с визуально интерполированным центром выбранного ковра, чтобы не отрываться и не прыгать между сетевыми снимками.

Для каждого собственного ковра хранить ограниченный буфер наблюдавшихся позиций за последние 50 секунд (монотонные timestamps snapshot). Рисовать путь истории для каждого ковра по умолчанию, соединяя его с текущей интерполированной позицией. Хвост рисовать приглушённо; для выбранного ковра использовать цвет основной прогнозной траектории, для остальных — цвет своего флота. Будущее выбранного маршрута рисовать ярко от точки соединения. Использовать только точки не позже `renderTime = now - pollInterval`, чтобы история и текущий прогноз совпадали по времени. Буфер не экстраполирует серверное движение и не изменяет физику/команды.

Когда bounty присутствовала в предыдущем snapshot и исчезла в новом, проверить swept-отрезки перемещения ковров между снимками. Если такой отрезок пересек круг bounty с радиусом `transportRadius + bountyRadius`, записать ее координату и время в ограниченный 10-секундный буфер собранных bounty конкретного ковра. Рисовать событие небольшим серым маркером поверх исторического пути только пока оно попадает в видимое временное окно. Исчезновение bounty без пересечения пути не считается сбором.

## 3. Управление интерфейсом

- Клик по своему живому ковру / клавиши `1`–`5`: выбрать наблюдение и следовать камерой. Клик по пустому месту снимает выбор. Выбор сам не включает ручное управление.
- `M` отдельно включает/выключает manual mode; указатель задает вектор ускорения от центра ковра с magnitude `min(distance, maxAccel)`. Координата Y переводится с учетом экранной инверсии.
- При первом mouse-векторе manual mode включить совместимый lease `lib/arena-bots/rust_bytadaniel/manual_control_<token-hash>.json` с тем же FNV-1a suffix, сроком через 1 секунду и уникальным `leaseId`; обновлять локальный lease каждые 200 ms и отправлять команду выбранному carpet сообщением `commands` по уже открытому WebSocket. При выключении/закрытии отозвать только собственный lease; snapshots продолжать читать из того же WebSocket без пустых `/move` запросов.
- Когда бот player_2 читает активный lease, его API цикл остается приостановленным по root FE-018 contract. Не делать параллельных ручных POST потоков.
- `P` включает fan. Колесо/`+`/`-` zoom; drag и стрелки панорамируют; `Space` включает follow; `R` сбрасывает обзор.

## 4. Проверки

- [ ] Alpha 0/0.5/1 дает ожидаемую координату, сущности по разным ID не смешиваются.
- [ ] Выбор не посылает ускорение, а `M` включает/выключает его отдельно.
- [ ] Лимит acceleration не зависит от zoom/DPI.
- [ ] Lease истекает при аварийном завершении и удаляется при штатном выходе.
