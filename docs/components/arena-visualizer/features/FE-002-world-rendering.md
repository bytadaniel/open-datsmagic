# FE-002: Аппаратно ускоренная отрисовка игрового мира

## 1. Контекст

Показать большую карту с плотной сценой без дорогих Python/Pygame per-primitive циклов.

## 2. Рендер pipeline

Сцена рисуется через `egui::Painter` в центральной панели; UI/HUD и интерактивные слайдеры — в том же кадре. World-to-screen переводит начало координат камеры в центр viewport, X вправо, Y вверх; экранная Y инвертируется. Zoom привязан к курсору; drag панорамирует камеру.

### Порядок слоев

1. Внешний фон и почти белая арена; coordinate grid выключена по умолчанию.
2. Если включено, тепловая карта результирующей силы аномалий с направляющими векторами. Отдельно управляемые полупрозрачные зоны аномалий можно скрыть, оставляя сплошные ядра.
3. Радиус физического диска bounty равен `apiRadius × worldToScreenScale`; к нему не применяется минимальный экранный радиус. Толщина его контура также масштабируется из world-space. Если физический диск становится субпиксельным (`<0.75 px`), дополнительно рисуется компактная точка только для обозначения центра/наличия bounty; она не кодирует физический радиус.
4. Траектории, ауры и тела ковров с индексами флота.
5. Три вектора каждого ковра: V velocity, S selfAcceleration, W anomalyAcceleration. Векторы начинаются в центре транспорта, рисуются в screen-space шкале (скорость относительно `maxSpeed`, ускорения относительно `maxAccel`) с минимальной длиной 8 px для любого ненулевого значения; экранная длина не зависит от zoom. Пределы длины — 80 px для V, 64 px для S и 96 px для W. Наконечник компактный: длина 5 px, половина ширины 3 px. HUD показывает легенду цветов и точные компоненты выбранного ковра.
6. HUD: token/team, score, tick, FPS, connection, zoom, selected carpet, vectors and forecast score/time.

### Семантические цвета

- Арена: `#F8FAFC`, поле снаружи: светлый slate.
- Притяжение: красное полупрозрачное поле и непрозрачное красное ядро. Отталкивание: синее поле/ядро.
- Свои ковры: синие, вражеские: красные; их ауры соответственно янтарная и зелёная.
- Текущий путь: тёмно-синий; coin route: пурпурный; death: красный с крестом.

Сцена использует векторные primitive batching (насколько возможно через painter `extend`) и отсечение объектов вне видимого world rectangle до генерации фигур. Не создавать текстуры/Surface или аллокации на каждую монету каждый кадр.

## 3. Аномалии и монеты

Знак `strength` определяет тип аномалии по корневому API: отрицательная сила — repel blue, положительная — attract red. Размер ядра `radius`; зона силы `effectiveRadius`; позиции движущихся аномалий интерполируются между ответами по стабильному `id`, без декоративной анимации. В центре ядра белым показывается округлённая знаковая сила (`+35` притягивает, `−35` отталкивает; ноль — `0`). Непрозрачность заливки области воздействия монотонно растёт с `abs(strength)` и ограничивается диапазоном 8–36% opacity. У каждой аномалии показывается её API-вектор `velocity`: стрелка с экранной длиной 14–54 px относительно наибольшей скорости аномалий в snapshot и компактным наконечником, без обводки/подложки. Стрелка отталкивающей аномалии синяя, притягивающей — красная, как ядро. Это вектор движения аномалии; её скалярная `strength` не является вектором. Результирующее воздействие аномалий на ковер остаётся в ковровом векторе W (`anomalyAcceleration`). Все bounties видны на любом разумном zoom и остаются плоскими/компактными.

## 4. План и проверки

- Заголовок native window при запуске включает токен из обязательного `DATS_PLAYER_TOKEN`.
- Подписи своих ковров показывают API `id`, а не порядковый номер. Для врагов показывается API `id`, если он есть; legacy API без id получает уникальную подпись `enemy-NN` внутри текущего snapshot.
- HUD явно показывает текущие очки, число подтвержденных сборов bounty за сессию, смерти флота и оценку потерянных очков. Авторитетное число смертей — сумма серверных lifetime `deathCount`; переходы `alive`→`dead`/`destroyed` используются только как совместимый fallback. Потерянные очки считаются по балансу сессионного счета: стартовые очки + подтвержденные сборы bounty − текущие очки, с нижней границей 0.
- Боковая панель организована в компактный порядок: статус и счет; быстрые переключатели карты/наблюдения/ручного режима; сворачиваемые настройки прогноза, список ковров и подробности выбранного ковра. Подробные легенды и объяснения не занимают место постоянно.
- Подробности выбранного ковра включают player_2 telemetry по совпадающему carpet id: aim/movement/doom стратегии, выбранную цель и решение (`aim`, `escape`, no-escape), target/score/time-to-score/rate, риск и смерть, `A_next/A_now/W`, позицию и скорость. Сводка читается из token-scoped локального snapshot, обновляемого player_2; при отсутствии или устаревании источника интерфейс явно показывает это, не подменяя логи локальным прогнозом визуализатора.
