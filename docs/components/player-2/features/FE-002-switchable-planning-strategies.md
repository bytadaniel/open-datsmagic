# FE-002: Переключаемые стратегии планировщика player_2

## 1. Контекст и бизнес-цель

Сохранить действующую стратегию как основную и дать возможность быстро переключать игрока на экспериментальный маневренный режим. Оба режима используют один API-клиент, прогноз физики, оценку опасности и формат команды.

## 2. Архитектурное решение

`DATS_PLAYER_STRATEGY` выбирает aim-стратегию при старте: `stable-profit` (по умолчанию) или `agile-top1`. Независимо `DATS_MOVEMENT_STRATEGY` выбирает движение: `none` (по умолчанию, текущее поведение) или `survival`. `DATS_DOOM_POLICY` выбирает `collect` (по умолчанию: максимум фактических монет до гибели, затем дольше прожить) или `fastest` (максимальная скорость, затем кратчайшая смерть); политика используется только при `survival`, когда выживаемого направления не найдено. Настройки неизменны до рестарта. `Bot::new(horizon)` и `Bot::with_strategy(horizon, strategy)` сохраняют прежний API с движением `none`; `Bot::with_strategies` задаёт все режимы явно.

## 3. Схема базы данных

Не применяется. Состояние обеих стратегий находится в памяти процесса.

## 4. Алгоритмы и вспомогательные функции

### `stable-profit` — основная стратегия

- Горизонт по умолчанию 30 с; разрешена настройка через `DATS_PLAN_HORIZON_SECONDS`.
- Закрепляет ближайшую фактически собираемую bounty на безопасной траектории, контролирует ETA и удерживает курс.
- Выполняет короткий tactical scan выгодных detour-монет; после сбора detour повторно выбирает лучший маршрут по свежему состоянию. Исходный маршрут — один из кандидатов, а не обязательный возврат.
- Безопасность выше score; каждый живой ковер получает вектор полного ускорения.

### `agile-top1` — безынерционный выбор лучшего маршрута

- Горизонт по умолчанию 15 с; значение окружения ограничивается сверху 15 с.
- На каждом снимке заново оценивает ровно 360 направлений полного круга с шагом 1°, начиная от абсолютного угла 0°; каждый маршрут моделируется до 15 с с временным шагом 0,2 с.
- Среди безопасных маршрутов выбирает top-1 по `routeScore / timeToLastBounty` — той же метрике, по которой визуализатор ранжирует прибыльный веер. При равенстве rate tie-break: фактический total score, скорость и время первой монеты. Безопасный путь без score остаётся выше любого смертельного пути; если безопасных нет, сохраняется штатный выбор `FastestDeath`.
- Для `agile-top1` рассматриваются все bounty из Desert snapshot, не shortlist ближайших 64; пространственный grid ограничивает проверку монет ячейками около каждого swept-сегмента.
- Для совпадения с прогнозным веером визуализатора команда до применения удерживается 0,3 с; после этого моделируется постоянный вектор-кандидат полной длины `maxAccel`. Шаг физики — 0,2 с, Euler/friction/anomaly/collision/capture синхронизированы с серверной моделью.
- Не читает и не сохраняет `PlanMemo`, не удерживает цель/курс, не использует incumbent, порог выгоды или detour. Решение каждого тика зависит только от свежего Desert snapshot.
- Команда — `maxAccel` в направлении управляющего вектора выбранной top-1 траектории. Это первый управляющий шаг receding-horizon плана; на следующем тике вектор рассчитывается заново из обновлённых позиции и скорости.
- При равной безопасности должен сохраняться максимум скорости; если все направления смертельны, выбирается лучший доступный вариант цели `FastestDeath` с ненулевым ускорением.

### Движение независимо от aim

- Aim всегда строит обычный план на монеты (`stable-profit` или `agile-top1`). Movement-политика также запускается каждый тик и может переопределить только применяемое направление ускорения; aim не отключается и на следующем тике пересчитывается из нового состояния.
- `none` не добавляет movement override — сохраняется только безопасность, заложенная в aim-стратегии.
- `survival` каждый тик оценивает текущий aim-курс на горизонте 30 с. Пространственный шаг сетки оценки риска — 350 единиц мира; он не меняет шаг физического прогноза 0,2 с. Риск учитывает притягивающие аномалии и давление у границ карты, но сам по себе высокий накопленный риск не является причиной бросать сбор монет.
- Если aim-курс входит в фатальную ячейку risk-grid в пределах 30-секундного safety горизонта, выполняется круговой 5° scan (72 варианта), чтобы оценить число безопасных выходов. Сам факт будущего риска больше не переключает движение сразу: escape включается, когда до первого fatal-события осталось не больше 3 секунд либо безопасных вариантов не больше 10% скана (7 из 72). Иначе игрок продолжает aim, пока вариантов выхода достаточно; следующий тик обновляет оценку. Компенсируемое давление не запускает уклонение.
- Если escape включён и scan нашёл живые маршруты, сначала отбрасываются варианты без bounty, когда существует выживаемый вариант со сбором; собирающие маршруты ранжируются по `score_rate`, затем по фактическому score и скорости. При множестве безопасных альтернатив поздняя угроза не перебивает aim. Компенсируемое risk exposure не участвует в выборе и не служит tie-break; оно остаётся только телеметрией.
- Если ни одно из 72 направлений не переживает полный горизонт, это считается «выход не найден в scan/горизонте», а не математическим доказательством вечной смерти. `DATS_DOOM_POLICY=collect` выбирает фатальный маршрут по максимальным фактически пересечённым points, затем score-rate и более поздней смерти. `fastest` использует действующий приоритет максимальной скорости, затем кратчайшей смерти. В обоих режимах ускорение остаётся максимальным ненулевым.
- Телеметрия показывает risk exposure и принятое movement-решение (`aim`, `aim-options-open`, `escape-imminent`, `escape-scarce-options`, `no-escape-collect`, `no-escape-fastest`).

Быстрый запуск:

```sh
DATS_PLAYER_STRATEGY=stable-profit cargo run --release
DATS_PLAYER_STRATEGY=agile-top1 cargo run --release
DATS_PLAYER_STRATEGY=agile-top1 DATS_MOVEMENT_STRATEGY=survival DATS_DOOM_POLICY=collect cargo run --release
```

## 5. API-контракты и DTO

Изменений нет. Оба режима отправляют команды через `POST /play/magcarp/player/move` в одном Desert batch DTO.

## 6. Обработка ошибок

Неизвестное или пустое значение любой явно заданной strategy env-переменной завершается понятной ошибкой конфигурации; автоматического молчаливого перехода нет. Отсутствующие переменные используют значения по умолчанию. Остальные ошибки API обрабатываются общим клиентом.

## 8. Тестирование

- `TC-PLAYER-STRATEGY-01`: значение по умолчанию — `stable-profit`; допустимые имена разбираются, опечатка возвращает ошибку.
- `TC-PLAYER-STRATEGY-02`: `agile-top1` ограничивает горизонт 15 секундами, каждый тик выполняет scan/refinement заново и не фиксирует предыдущую цель или угол.
- `TC-PLAYER-MOVEMENT-01`: survival mode не меняет aim из-за компенсируемого давления; при попадании прогнозной траектории в фатальную зону выбирает среди безопасных маршрутов наиболее прибыльный маршрут со сбором; без выживаемого направления применяет выбранную doom policy.
- `TC-PLAYER-MOVEMENT-02`: риск-сетка имеет шаг 350 единиц мира и не меняет временной шаг физического прогноза 0,2 с.
- Прогнать `cargo test` для player_2 и проверить, что обе стратегии отправляют ненулевой вектор длины `maxAccel` для живых ковров.
