# DR-001: Запуск Java-клиента и подключение к арене

## 1. Бизнес-контекст

**Проблема / Возможность:** сохранённая Java-реализация по умолчанию проигрывает fixture-файл, а запросы к API отключены; адрес сервера и токен зашиты в исходниках.

**Цель:** запускать существующий Java-клиент либо как просмотрщик сохранённых состояний, либо как игрок на выбранной арене, передавая настройки окружением.

**Пользователи / Роли:** владелец команды запускает процесс и предоставляет зарегистрированный Hub токен.

**Ключевые метрики:** API-запросы ограничены частотой ниже серверных 5 запросов/с на токен; задержка вычисления и HTTP-ответа видна в консоли.

## 2. Сценарии использования

### 2.1 Основной сценарий (Happy Path)

| № | Участник | Действие | Результат |
|---|---|---|---|
| 1 | Игрок | Устанавливает `DATS_GAME_MODE=api`, `DATS_PLAYER_TOKEN` и `DATS_GAME_API_URL` | Клиент проверяет конфигурацию до первого запроса |
| 2 | Клиент | Посылает пустой валидный пакет, затем рассчитанный пакет ускорений | Arena возвращает Desert snapshot, клиент обновляет визуализацию и рассчитывает следующий пакет |
| 3 | Arena | Проверяет `X-Auth-Token` и применяет пакет по игровому контракту | Игра продолжается без изменения алгоритма Java-клиента |

### 2.2 Альтернативные сценарии

- Без `DATS_GAME_MODE=api` клиент остаётся в офлайн-режиме и читает `response_pack.txt`.
- `DATS_SHOW_VISUALIZATION=false` запускает цикл без окна; звук по умолчанию отключён.

### 2.3 Исключительные ситуации (Error Path)

| Условие | Реакция системы |
|---|---|
| В API-режиме отсутствует токен | Завершить запуск с понятной ошибкой, не отправлять запрос |
| API вернул `401` или `400` | Вывести код ошибки и прекратить API-цикл |
| API вернул `429` | Вывести статус и выдержать паузу перед следующим запросом |
| Сеть/сервер временно недоступны | Вывести ошибку и повторить после паузы; не отправлять быстрый цикл ретраев |

## 3. Функциональные требования

| ID | Требование | Приоритет | Примечание |
|---|---|---|---|
| FR-01 | Поддерживать офлайн-fixture и API-режим | Must have | API включается только явно через `DATS_GAME_MODE=api` |
| FR-02 | Читать токен и URL из окружения | Must have | Не хранить токен в репозитории или аргументах запуска |
| FR-03 | Начинать API-сессию с валидного пустого JSON-пакета | Must have | Не посылать пустую строку |
| FR-04 | Сериализовать рассчитанные `transports` согласно Desert API | Must have | `X-Auth-Token` передаётся HTTP-заголовком |
| FR-05 | Соблюдать безопасную частоту API-запросов и обрабатывать HTTP-ошибки | Must have | Не более 5 HTTP-запросов/с на токен |

## 4. Нефункциональные требования

| ID | Требование | Значение / Описание |
|---|---|---|
| NFR-01 | Секреты | Токен не печатается в логах и не хранится в коде |
| NFR-02 | Совместимость | Java 11+ и локальные Jackson JAR из `lib/` |
| NFR-03 | Ограничение API | Цикл отправляет не чаще одного запроса примерно за 350 мс; 429 обрабатывается паузой |

## 5. Бизнес-правила

1. Игровой API — `POST /play/magcarp/player/move`; авторизация — только `X-Auth-Token`.
2. Первый запрос сессии содержит `{"transports":[]}`; последующие содержат пакет `transports` рассчитанного игроком.
3. Наличие токена само по себе не включает сетевой режим: требуется явное `DATS_GAME_MODE=api`.
4. Алгоритм выбора направления/ускорения не меняется в рамках настройки запуска.

## 6. Модель данных (логическая)

| Сущность | Описание | Ключевые атрибуты |
|---|---|---|
| `RuntimeConfig` | Настройки режима процесса | `DATS_GAME_MODE`, `DATS_PLAYER_TOKEN`, `DATS_GAME_API_URL` |
| `DesertSnapshot` | Состояние арены, разобранное Jackson | `transports`, `bounties`, `anomalies`, `enemies`, `mapSize` |
| `PlayerAction` | Ответ планировщика, посылаемый серверу | `transports[].id`, `acceleration`, опциональные игровые поля |

## 7. API-контракты (со стороны бэкенда)

Клиент использует только `POST /play/magcarp/player/move`, описанный в [`DR-009`](../../domain/DR-009-legacy-world-contract.md). Формат — `{ "transports": [...] }`; полный контракт и примеры находятся в [справочнике API Hub](../arena-hub/api.md).

## 8. Критерии приёмки (Acceptance Criteria)

- [ ] AC-01: Fixture-режим продолжает запускаться без API-токена.
- [ ] AC-02: API-режим без `DATS_PLAYER_TOKEN` завершается до сетевого вызова.
- [ ] AC-03: Первый API-запрос — валидный пустой пакет; последующие содержат рассчитанные действия.
- [ ] AC-04: Токен передаётся заголовком, а endpoint берётся из `DATS_GAME_API_URL`.
- [ ] AC-05: `401`/`400` не образуют бесконечный цикл запросов; `429` получает паузу.

## 9. Вопросы и допущения

**Допущения:** сервер совместим с зафиксированным Desert API; содержимое `DATS_GAME_API_URL` — полный URL игрового move endpoint.

## 10. Зависимости

- **Внешние системы:** активный сервер StadMagic и зарегистрированный токен Hub.
- **Внутренние модули:** Java-клиент `lib/arena-bots/java_sas4eka`, Jackson JAR в его `lib/`.
- **Инфраструктура:** JDK 11+, сеть до Hub/Arena.
