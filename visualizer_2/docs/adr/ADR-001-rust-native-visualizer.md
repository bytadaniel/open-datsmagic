# ADR-001: Автономный нативный Rust-визуализатор

## Контекст

Python/Pygame-клиент опускается до неприемлемой частоты кадров на полной сцене и веере прогнозов. Нужен отдельный нативный клиент без встраивания графических зависимостей в серверный или игровой бинарник.

## Решение

- Новый автономный crate размещается в `visualizer_2/`; существующий `visualizer/` остается нетронутым как fallback и для сравнения.
- Окно, ввод, UI и аппаратно ускоренная отрисовка реализуются на Rust через `eframe`/`egui` с renderer `glow`.
- REST-опрос выполняется отдельным рабочим потоком; кадр рисуется независимо от сети. Канонический Desert API и токеновый контракт берутся из корневых `docs/`, реализации сервера и `./datsmagic`.
- Визуализатор остается отдельным исполняемым файлом. Его зависимости не входят в бинарник сервера.
- Предиктор использует единый описанный контракт физики и bounty scoring, но не становится источником команд для player_2.

## Последствия

- Плотный веер и множество точек обрабатываются без Python-цикла и Pygame draw-call на каждую точку.
- Требуются Rust toolchain и системная графическая поддержка; окно и network worker проверяются независимо.
- Любые изменения API сначала сверяются с корневыми серверными спецификациями; детали интерфейса и рендера принадлежат этой папке.

## Источники

- [Официальная документация eframe](https://docs.rs/eframe/latest/eframe/): нативное приложение через `App` и `run_native`.
- [Официальная документация egui Painter](https://docs.rs/egui/latest/egui/struct.Painter.html): пакетное добавление 2D-фигур для отрисовки сцены.
