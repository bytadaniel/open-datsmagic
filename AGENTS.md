# Руководство для AI-агентов

Проект использует Spec-Driven Design. `docs/` — единый источник правды для механики, API, архитектуры и поведения всех компонентов. До изменения реализации изучите подходящие ADR, Domain Records и Feature Specs; при изменении требований сначала обновите спецификацию, затем код и тесты.

## Карта проекта

| Путь | Ответственность |
|---|---|
| `lib/arena-server/` | Rust-симуляция, игровой API и процесс арены |
| `lib/arena-visualizer/` | Автономный Rust/egui визуализатор |
| `lib/bot-variants/<player>/` | Независимый код конкретного игрока/бота; не смешивать с серверной логикой |
| `apps/arena-hub/` | Python control plane, веб-интерфейс, API и управление жизненным циклом арен |
| `assets/worlds.json` | Единственный каталог конфигураций миров |
| `docs/adr/`, `docs/domain/`, `docs/features/` | Общая архитектура, доменная логика и серверные/платформенные фичи |
| `docs/components/<component>/` | Спецификации компонента с его локальной нумерацией |

## Правила

- Не зашивайте мировые настройки, контракты или эвристики в обход документации.
- Не добавляйте визуализаторские зависимости в `arena-server`; визуализатор и боты общаются с сервером через API.
- Не переносите поведенческий код ботов в сервер.
- Не коммитьте token-файлы, runtime-данные, локальные базы/логи и сборочные артефакты.
- Для файловых правок используйте `apply_patch`; сохраняйте существующие несвязанные изменения пользователя.
- После правок запускайте релевантные тесты и проверки ссылок/формата документации.

Архитектура монорепозитория зафиксирована в [`ADR-003`](docs/adr/ADR-003-repository-layout.md). Шаблоны SDD: [`Domain Record`](docs/DOMAIN_RECORD_TEMPLATE.md) и [`Feature`](docs/FEATURE_TEMPLATE.md).
